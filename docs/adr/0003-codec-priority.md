# ADR 0003: コーデック優先順位 AV1 > H265 > H264 > VP9 > VP8

**状態**: 承認 (2026-04-29)

## コンテキスト

複数のビデオコーデックをサポートする中で、ホスト・ビューア両者が対応する
最良のコーデックを自動選択する。

## 判断

優先順位 (高→低):
1. **AV1**
2. **H265 (HEVC)**
3. **H264 (AVC)**
4. **VP9**
5. **VP8**

## 理由

### AV1 を最優先
- 同品質で H265 より 30%、H264 より 50% 帯域削減
- ロイヤリティフリー (AOMedia)
- HW エンコード対応広がり中: NVIDIA RTX 40+, Intel Arc, AMD RX 7000+
- HW デコード: 2023年以降のチップは大半対応
- スクリーンコンテント (テキスト・UI) で特に効果大

### H265
- HW エンコード/デコード成熟
- macOS VideoToolbox で高速
- Apple Silicon ネイティブ対応
- 弱点: ライセンス (HEVC Advance + MPEG LA + Velos Media)

### H264
- 全環境で動作 (互換性最強)
- 効率は劣るが帯域余裕がある場合 OK
- HW エンコードどこでも

### VP9 (現在のソフトウェア・デフォルト)
- libvpx で純ソフト動作 (HW不要、即動作)
- AV1 が利用不可な環境のフォールバック
- リアルタイム圧縮効率は H264 と同等

### VP8
- 後方互換のみ — 新規採用しない
- 将来削除予定 (v2.0)

## 動的選択

`miru-common::codec::negotiate(host_codecs, viewer_codecs)` で
両者の交差集合から最高優先度を選択。

## 結果

- v0.1 (現状): VP9 ソフトウェアのみ動作
- v0.3 目標: AV1 HW エンコード (NVENC/QSV) 統合
- v1.0 目標: 全 HW backend サポート
