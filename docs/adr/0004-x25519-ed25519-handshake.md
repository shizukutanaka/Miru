# ADR 0004: X25519 + Ed25519 + HKDF ハンドシェイク

**状態**: 承認 (2026-04-29)

## コンテキスト

セッション暗号化のための鍵交換方式の選択。脅威モデル:
- リレーサーバー: 信頼しない (見えるのは暗号文のみ)
- シグナルサーバー: 信頼しない (鍵交換に介入させない)
- 中間者攻撃 (MITM): 検出可能であること
- リプレイ攻撃: 防止すること
- Perfect Forward Secrecy: 過去のセッション鍵漏洩しても旧通信を復号できないこと

## 候補

- TLS: 重い、PKI前提、自己署名は警告問題
- Noise Protocol Framework (XK パターン等): 良いが学習曲線急
- 自前 X25519 + Ed25519: シンプルかつ実証済み

## 判断

下記プロトコルを採用:

1. 各デバイスは Ed25519 keypair を永続保持 (identity)
2. セッション開始時に X25519 ephemeral keypair を生成
3. 双方が「ephemeral pubkey + identity pubkey + Ed25519署名(challenge)」を送信
4. challenge = "miru-handshake-v1" || eph_pub || identity_pub
5. 共有秘密 shared = X25519(own_eph_secret, peer_eph_pub)
6. session_key = HKDF-SHA256(shared, salt=session_id, info="miru-session-v1")
7. identity pubkey は TOFU (Trust On First Use) で固定

## 結果

- ✓ Perfect Forward Secrecy (ephemeral keypair)
- ✓ Identity 認証 (Ed25519 signature over challenge)
- ✓ HKDF で session_id ごとに独立した鍵
- ✓ シンプル (実装 ~300行)
- ✓ ライブラリ: x25519-dalek, ed25519-dalek, ring (HKDF) すべて audited
- ✗ TOFU は最初の接続で MITM される脆弱性 → 対策: 6桁PIN + 指紋表示
- ✗ Post-quantum 非対応 → 将来 ADR で Kyber768 ハイブリッド追加 (v2.0計画)
