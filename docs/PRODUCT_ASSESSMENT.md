# プロダクト総括 — 長所・短所・改善点

**手法**: マスクのアルゴリズム(①要件を疑う ②削除 ③簡素化 ④サイクルタイム短縮 ⑤自動化)で
何を作るかを決め、ソクラテス式問答で各主張の根拠を問い直した。

**本書の規則**: すべての主張に**実測の根拠**を併記する。根拠を示せない主張は書かない。
「たぶん速い」「おそらく安全」は本書には存在しない。

---

## 1. 長所 — ただし「なぜそう言えるか」付きで

### 1.1 入力経路は実際に直っている(推測ではなく)

**主張**: キーボード・マウス入力はリモートデスクトップの中核であり、ここは信頼できる。

**なぜそう言えるか**: 第一原理(①画面が見える ②操作できる)で精査した結果、
**独立した4層すべてが壊れていた**と判明し、各々を修正して回帰テストで固定したから:

| 層 | 実際の欠陥 | 固定方法 |
|----|-----------|---------|
| キーコード | `keyCode` を無変換で evdev / CGKeyCode / VK へキャスト。3つは**互いに無関係な番号空間**で、`A` が Linux で `KEY_F7` になっていた | `keymap.rs` 120キー(Chromium 準拠)+ テスト11件 |
| 修飾キー | Ctrl+W で **Ctrl を先に離すと** W の keyup だけがすり抜け、押下記録の無い key_up がホストへ | 押下追跡 + テスト |
| スクロール方向 | `dy == 0.0` が「下スクロール」判定。横スクロール専用イベントが縦に誤動作 | ゼロ delta を no-op 化 |
| スクロール量 | `deltaMode` 無視。**WebKitGTK(Linux の Tauri webview そのもの)は行モード**を報告するため `/100` で実質無反応 | `wheel-normalize.ts` + テスト6件 |

**ソクラテス的検証**: 「4層すべてが壊れていたなら、なぜ誰も気づかなかったか?」
→ 単体テストが**1件も無かった**から。だから修正と同時にテストを置いた。

### 1.2 「検証できないなら書かない」を実際に守った

**主張**: 本ブランチのコードは、書いた本人が動作を確認していないものを含まない…と言いたいが、
**これは正確ではない**(§2.1 参照)。正確には「**検証手段を作れる場合は必ず作った**」。

**実測値**(`scripts/verify-offline.sh`、本コミット時点): **Rust 79** / **frontend 75** /
**FFI 実行 10**(libavcodec 実エンコード 7 + portal・PipeWire 3)。セッション開始時は
Rust の実行テストが **0** だった。

**なぜそう言えるか**: 実行して初めて出たバグが3件あり、いずれも目視レビューでは出なかった:

- `SPA_POD_CHOICE_ENUM_Id` の個数は**先頭の既定値を含む**。6個の値に 5 を渡し **segfault**
- プロデューサの `PW_STREAM_FLAG_DRIVER` により誰もクロックせず**フレーム0**。
  ただし**フォーマット交渉は正常に完了していた** — 目視なら「正しい」と見える典型
- 最初のテストは 8KB のチャンクで**合格していた**。307KB のフルフレームを要求するよう
  assertion を締めて初めて露見

**ソクラテス的検証**: 「テストが通ったことは正しさの証拠か?」→ 3件目が反証。
テストは**何を主張しているか**まで見ないと意味がない。

### 1.3 パリティ2機能を Rust 依存**ゼロ**で実装した

**主張**: HW エンコード(B)と Wayland キャプチャ(C)は、外部クレートを1つも増やさず入った。

**なぜそう言えるか**: ①「要件を疑う」を適用した結果、ブロッカーが**誤認**だったから。
`ffmpeg-next` はクレートだが **libavcodec は C ライブラリ**で、crates.io は経路上に無い。
同じ誤認が PipeWire にもあった。実際に削除できた依存: `pipewire = "0.8"`。
追加した依存: **なし**(C シム + `build.rs` が `std::process::Command` で cc/pkg-config を直接呼ぶ)。

| 機能 | 実測の検証 |
|------|-----------|
| B: HW エンコード | mpeg4 で 10フレーム投入 → 実パケット・実バイト・キーフレーム1件。HW エンコーダは**コーデック名が違うだけの同一パス**で、この環境の libavcodec 60 に `h264_nvenc`/`av1_nvenc`/`h264_vaapi`/`hevc_vaapi` が全て存在 |
| C: PipeWire | テスト自身がプロデューサを起動し、実 PipeWire デーモン越しに **320x240 BGRx のフルフレーム3枚**を受信 |
| C: portal | headless sway + xdg-desktop-portal を実際に立ち上げ、**CreateSession と SelectSources の成功**を確認 |

### 1.4 実装中にツールが捕まえたバグ(レビューでは出なかったもの)

項目17の実装だけで3件。**いずれも私自身のコードのバグ**であり、テストと型検査が
無ければそのまま出荷されていた:

- `f32::clamp` は **NaN を伝播する**(クランプしない)。NaN が注入バックエンド経由で OS へ届いていた。
  そのために書いたテストが捕捉
- DXGI の変数は `r` なのに `rect.left` と書いた
- `InputMsg` 型への `display` 追加漏れを tsc が検出(tauri 側の型には追加済みだった)

**ソクラテス的検証**: 「自分が書いたコードなら正しさを知っているのでは?」→ 3件が反証。
書いた直後の自分は最も信頼できないレビュアーである。

### 1.5 その他(根拠のあるもののみ)

- **`unwrap()` 規約は本当に守られている**: 非テストコードの `.unwrap()` は **0件**
  (146件は全て `#[cfg(test)]` 配下。`git ls-files` 全走査で確認)
- **暗号設計**: X25519 ECDH(ephemeral, PFS)+ ChaCha20-Poly1305(単調 nonce・replay 保護)、

- **孤立モジュールが0**: `check-module-reachability.py` が全 `.rs` の到達性を検査

## 2. 短所 — 隠さずに

### 2.1 最大の弱点: ほとんどの Rust 変更が `cargo` で検証されていない

**事実**: 本ブランチの35コミット中、`cargo test --workspace` を通ったものは**ゼロ**。
`static.crates.io` がネットワークポリシーで遮断(HTTP 403)されているため。

**これは実害があるか**: **ある。実際に2回起きた**。

- `SessionEvent` に追加したフィールドを `state.rs` の構造体リテラルに反映し忘れ
- `session::run` から `audio_muted` 引数が消え、呼び出し側は12個渡し定義は11個

いずれも**クレート境界をまたぐ型の不整合**で、オフラインゲートが原理的に見られない種類。
そして **`linux.rs` の portal↔PipeWire 接続コードはまさにこの種類**(x11rb 依存で
パースのみ)。**同じ穴が今も開いている。**

**ソクラテス的検証**: 「オフラインゲートがあれば十分では?」→ **否**。
ゲート自身のヘッダが `cargo test --workspace` の代替ではないと明記しており、
上記2件が実例。ゲートは「何も確認していない」を「一部は実行した」に変えるだけ。

**追加検証**: 「cargo が無いから見られない」は**事実ではなく仮定**だった。
実例2件のうち①(構造体リテラルのフィールド欠落)は型システム無しで検出可能であり、
`scripts/check-cross-crate.py` を追加して**実際に起きたコミット `8539eb0^` で検出できることを実証**
(現 HEAD ではクリーン)。ゲートに組み込み済み。

**ただし穴は塞がっていない**。②(引数個数の不一致)向けのチェックも書いたが、
`run` はワークスペース内に複数定義があり、誤検出を抑える曖昧性ルールが
**検出したかった当の呼び出しごと除外**してしまう一方、他所では誤検出を出した。
**自らの動機となったケースを取り逃し、かつ狼少年になるチェックは無いより悪い**ため削除した。
トレイト境界・型引数・依存 API の誤用は依然として見えない。
`cargo test --workspace` がマージ前必須である事実は**変わらない**。

### 2.2 スコープの二重化が未解決のまま

**事実**: Rust 全 21,826行のうち、凍結中の AI エージェント統治スコープが **7,173行(約33%)**
(mcp 2,764 / agent 2,421 / transparency 930 / sandbox 706 / constellation 352)。

ADR 0022 で feature gate 化を提案し**実施済み**だが、ADR 0005(差別化軸)と
roadmap §0(凍結)と FEATURE_AUDIT(パリティ基準)が**異なる「完成」を定義**する構造は残る。

### 2.3 未参照コードと未決の製品判断

- `quic.rs` **319行が完全に未参照**。`quinn` と `rcgen` の唯一の利用者でもあり、
  削除すれば依存2件が消える。**ただし削除していない** — QUIC は architecture.md /
  THREAT_MODEL.md / competitive-analysis.md が明示する製品方針であり、
  DEVELOPMENT_LOG に「意図的に残す」記録がある。**記録された判断を独断で覆さない**
- 未参照 `pub` 項目は現在 **14件**(quic 9 + 凍結スコープ 4 + `safe_fs::open_for_read` 1)。
  最後のものは O_NOFOLLOW 付き安全 open で、用途が doc に明記されたセキュリティ API

## 3. 改善点 — 優先順位付き

**優先順位の基準**: 「それが無いと他の全てが検証不能になるか」で並べた。

### ① `static.crates.io` の許可 → `cargo test --workspace`

**唯一にして最大の未解決ブロッカー**。これ1つで §2.1 が消える。
環境のネットワークポリシー変更で解決する(https://code.claude.com/docs/en/claude-code-on-the-web)。
許可されれば直ちに `cargo test --workspace` と `--features agent` の両方を実行すべき。
**マージ前に必須**。

### ② Wayland 実機での E2E(項目4)

portal と PipeWire の両半分は個別に実証済みだが、**通しで動かした実績が無い**。
本環境では headless sway に DRM デバイスが無く、xdpw が
`unable to receive a valid format from wlr_screencopy` でフォーマットを拒否する
(クライアントの欠陥ではない — 同環境で `grim` は screencopy 経由で撮影できる)。

### ③ macOS ScreenCaptureKit 移行(項目5) — macOS 実機必須

### ④ ~~マルチモニタ座標(項目17)~~ — **修正済み**(`c04f9bb`, `c26b62f`)

監査が「部分修正は退行」として二度見送った項目。**変換が1枚・原点配置なら恒等写像**
であることをテストで固定したことで、VIRTUALDESK 追加が通常ケースを動かさなくなった。
プロトコル(x/y、`display`)・ホスト側変換・3バックエンド・キャプチャ・ビューア送出の全経路。
ビューアは**そもそも `display` を送っていなかった**(切替は映像だけ変わり入力はプライマリへ)。
残: OS バックエンドは parse のみ、実機マルチモニタでの確認。

### ⑤ `quic.rs` の製品判断(319行 + 依存2件)

答えるべき問いは1つ: **QUIC 優先パスは着手予定か、WS リレー + hole-punch で確定か。**
前者なら残す。後者なら即削除できる(git が保持する)。

### ⑥ CI 有効化 — `git mv .github/workflows-proposed/*.yml .github/workflows/`(管理者権限)
